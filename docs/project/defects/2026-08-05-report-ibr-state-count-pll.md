# Report IBR state count and PLL-ownership misstatement

- **ID:** DOC-2026-08-05-01
- **Status:** RESOLVED
- **Area:** IEEE14 switching report (`docs/source/report_ieee14_switch_en.tex`)
- **Branch / commit at discovery:** `main` @ `126ae57`
- **Environment:** Windows 11 Pro 10.0.26200, TeX Live 2026 (XeLaTeX), MATLAB project tree
  `D:\Project\Power-flow`

## Symptom

The English switching report described the per-IBR switching superset as **18 states**, listed
only **11** grid-forming state symbols, and asserted that the grid-forming branch *"has no PLL
state: the angle and frequency reference are generated by the virtual-swing states"*.

This is a documentation defect only. No production numerical path, gate, parameter, or cached
result was affected; the trajectory and every reported number were produced by the correct model.

## Reproduction

1. Read `docs/source/report_ieee14_switch_en.tex` §2 (pre-fix lines 70--78).
2. Compare against the model that actually produces the 160-s trajectory:
   `scripts/reporting/generate_ieee14_switch_report_figures.m` calls
   `stability.run_hybrid_case` with `cases.scenario_ieee14_1sg_4ibr(case_profile='eecon49_figure4')`;
   that profile sets `model_id='regfm_b1_dual'` (`+cases/scenario_ieee14_1sg_4ibr.m:162`), which
   `+stability/build_mixed_resource_devices.m:122` dispatches to `ibr.dual_mode_ibr_model`.
3. Count the state names in each branch.

## Root cause with evidence

The report text was carried over from an earlier reduced-order design and never updated when the
production route moved to the 20-state dual superset.

| Claim in report | Source evidence | Verdict |
|---|---|---|
| 18-state superset | `+ibr/dual_mode_ibr_model.m` `contract_nx = 20`; `+ibr/regfm_b1_vsg_model.m:342` `nx=13`; `+ibr/wecc_regca_reeca_model.m:110` 7 names | wrong: 13 + 7 = 20 |
| 11 GFM state symbols | `+ibr/regfm_b1_vsg_model.m:342-344` lists 13 | wrong: `delta_PLL`, `x_PLL_int` omitted |
| GFM has no PLL state | same lines list `delta_PLL`, `x_PLL_int`; RHS `+ibr/regfm_b1_vsg_model.m` implements `d_x_PLL_int = Vq`, `d_delta_PLL = omega0*(kpPLL*Vq + kiPLL*x_PLL_int)`, frozen below `VPLLfrz` | wrong for GFM |

The "no PLL" statement is true of two other in-repo models that are **off** this report's path:
`+ibr/gfm_reduced6_model.m` (which explicitly rejects any PLL option) and the WECC GFL branch,
whose interface aligns algebraically via `exp(1i*angle(V))` in
`+ibr/wecc_regca_reeca_model.m`. The defect is that the report attributed the GFL/reduced-model
property to the production GFM branch.

## Falsified hypotheses

- *The report's trajectory came from the 6-state `SwitchableIbr6`/`gfm_reduced6_model` route,
  making "18 states" and "no PLL" self-consistent.* Falsified by the dispatch chain above, and
  independently by the fact that the reduced route cannot represent the SG reclose/handback that
  the report documents at 147.175 s.

## Fix

`docs/source/report_ieee14_switch_en.tex` §2 was rewritten: the superset is stated as 20 states,
both PLL states appear in `x_GFM`, the false sentence was removed and replaced by the accurate
split (GFM owns a PLL pair; the WECC GFL current-source branch owns none), and all 13 GFM and 7
GFL derivatives are now written term by term with units, bases, limiter/anti-windup behaviour, and
source classification. A new section states the hybrid-DAE switching formulation.

## Verification

- Every state symbol and its order cross-checked against `+ibr/regfm_b1_vsg_model.m:342-344` and
  `+ibr/wecc_regca_reeca_model.m:110`.
- XeLaTeX build of the report completes, 12 pages, no undefined references after the second pass.
- Documentation-only change: no production numerical or runtime contract was touched, so the full
  repository regression was intentionally omitted under the repository risk policy. Static build
  and source cross-check were the gates run.

## Limitations

The corrected text describes the model as implemented. It is not an independent validation of the
REGFM\_B1 G2 or WECC parameterisation against field measurements.
