Exact Lazy Search Pipeline

แผนขยาย Generic Mixed-Resource IBR Selector ให้รองรับ IBR จำนวนมาก โดยลดจำนวนครั้งที่ต้องรัน Power Flow / mixed equilibrium และ SSSA แต่ยังคงผลลัพธ์ที่ตรวจสอบย้อนกลับได้ เป็น deterministic และไม่ตัด candidate ที่ดีที่สุดด้วย heuristic ที่พิสูจน์ไม่ได้

สถานะเอกสาร: proposed architecture — ยังไม่ใช่ production behavior ที่ส่งมอบแล้ว
ขอบเขต: candidate generation, safe pruning, ordered evaluation, fail-closed search และ index contract

1. ปัญหาที่ต้องแก้

หากมี IBR ที่สลับ GFL/GFM ได้จำนวน N ตัว การ enumerate ทุก subset จะมี 2^N รูปแบบ สำหรับ IEEE14 ปัจจุบันมี 4 IBR จึงมีเพียง 16 รูปแบบและ exhaustive search เหมาะมากในฐานะ oracle แต่เมื่อมี 20 IBR จะเพิ่มเป็น 1,048,576 รูปแบบ การรัน nonlinear equilibrium และ eigenvalue analysis ให้ครบทุกแบบจะมีต้นทุนสูงเกินจำเป็น

เป้าหมายไม่ใช่การเปลี่ยน selector ให้เป็น heuristic selector
เป้าหมายคือยังได้คำตอบตาม ranking contract เดิม แต่สร้างและประเมิน candidate เท่าที่จำเป็น พร้อมตัดทิ้งเฉพาะกรณีที่มีหลักฐานว่าเป็นไปไม่ได้จริง

Exact

หยุดค้นหาได้ต่อเมื่อพิสูจน์แล้วว่า candidate tier ที่ยังไม่ประเมินไม่สามารถชนะ tier ปัจจุบันตาม ranking contract

Lazy

สร้าง candidate ทีละ tier และทีละชุด ไม่สร้างรายการ 2^N ทั้งหมดไว้ในหน่วยความจำตั้งแต่ต้น

Fail-closed

หากหมด candidate/time budget ก่อนพิสูจน์คำตอบ ให้รายงาน SEARCH_INCOMPLETE และห้าม commit “best so far” อัตโนมัติ

2. Index คืออะไร และทำไมต้องใช้แบบนี้

Resource index ไม่ใช่ bus number, generator-row index หรือ state index
ตัวเลข 2 ใน selected_gfm_indices = [2 3 4 5] หมายถึง resource ลำดับที่ 2 ใน canonical resource/device table ของ scenario นั้น ต้อง resolve กลับไปหา stable device_id และ external bus ได้เสมอ
ชื่อ ความหมาย เหตุผลที่มี สิ่งที่ห้ามตีความ
resource index ตำแหน่งใน canonical resource table ซึ่งรวม SG และ IBR ตาม ordering ที่ fingerprint รับรอง ใช้เชื่อม selector, device model, capability, dispatch และ event state ด้วย identity เดียวกัน ไม่ใช่หมายเลข bus และห้าม hard-code โดยไม่ validate resource ID
selected_gfm_indices เซต resource indices ของ IBR ที่อยู่ใน physical GFM mode และ online ใน committed configuration บอก “ใครบ้างเป็น GFM” แยกจาก “ใครเป็น reference owner” ไม่ใช่ reference เพียงตัวเดียว และไม่จำเป็นต้องเท่ากับทุก IBR
reference_owner_indices เจ้าของ supervisory/physical reference หนึ่ง resource ต่อ energized island อาจเป็น SG หรือ GFM รองรับ SG handback และ multi-island โดยไม่ผูกกับ MATPOWER REF bus ไม่ใช่การแทน KCL row หรือเพิ่ม slack bus ใน TS
gfm_reference_resource_indices GFM numerical reference ต่อ island ใช้เฉพาะขณะที่ island นั้นไม่มี SG เป็น reference owner แยก numerical GFM reference ออกจาก physical reference ownership ต้องว่างใน island ที่ SG ครอง reference
reference_island_ids island identity ที่จับคู่กับ owner/reference arrays ทำให้ validation ตรวจได้ว่าทุก energized island มี owner หนึ่งตัวและไม่มี duplicate owner ไม่ใช่ zone จาก electrical-distance clustering
n_gfm_required จำนวน GFM เป้าหมายของ candidate context เป็น cardinality constraint หรือ search tier ตาม policy ไม่เท่ากับจำนวนอุปกรณ์ที่ต้องเปลี่ยนโหมด
n_mode_changes Hamming distance ระหว่าง committed runtime modes ปัจจุบันกับ candidate target สะท้อนจำนวน transfer operations จริงและใช้ ranking candidate ที่รบกวนน้อยกว่า ห้ามคำนวณจากค่าที่ cache ไว้โดยไม่เทียบ runtime configuration ปัจจุบัน
bus position / external bus ID ตำแหน่ง internal network matrix และหมายเลข bus ภายนอกของ resource ใช้สร้าง Ybus, island membership, SCR และ electrical distance ไม่ควรใช้แทน resource identity
state index ตำแหน่ง state ของ device ใน composite DAE vector ใช้ numerical residual/Jacobian และ transfer maps ไม่ใช่ selector identity และเปลี่ยนได้ตาม active mode/state layout

ตัวอย่างที่ชี้ว่าจำนวน GFM ไม่เท่ากับจำนวน switches

  • Current GFM = {2,3,4,5}, target = {2,3,4}: n_gfm_required=3 แต่ n_mode_changes=1
  • Current GFM = {2,3,4}, target = {5,6,7}: n_gfm_required=3 แต่ n_mode_changes=6

เพราะฉะนั้นการกำหนด “GFM สูงสุด 3 ตัว” ไม่ใช่กลไกเดียวกับ “สลับพร้อมกันสูงสุด 3 ตัว” ค่าแรกจำกัด physical configuration ส่วนค่าหลังจำกัด transaction disturbance หากต้องใช้ข้อจำกัดใด ต้องกำหนดชื่อและ provenance ให้ตรงความหมาย

3. แบ่ง filter เป็น 3 ประเภทก่อนใช้งาน

  1. HARD-SAFE Necessary-condition filter
    • ตัด candidate ได้เมื่อพิสูจน์ว่า candidate นั้นไม่มีทาง feasible
    • ตัวอย่าง: energized island ไม่มี voltage-forming source, capability ไม่รองรับ GFM, conservative headroom upper bound ต่ำกว่าความต้องการ
    • ทุกการ reject ต้องมี structured reason และ evidence
  2. ORDER ONLY Search-order heuristic
    • ใช้เลือกว่าจะประเมิน candidate ใดก่อน แต่ห้ามลบ candidate จาก feasible set
    • ตัวอย่าง: electrical distance, zonal spread, dV/dQ, weak-bus score
    • เปลี่ยน heuristic ได้โดยผลสุดท้ายต้องเหมือน exhaustive oracle
  3. FULL GATE Nonlinear / dynamic acceptance gate
    • mixed equilibrium / full KCL
    • device current and capability limits
    • full-state SSSA และ frozen stability margin gamma_req

4. Exact Lazy Search Pipeline — ลำดับการทำงาน

  1. รับ authenticated runtime context

    • network topology และค่า Ybus ที่เกี่ยวข้องครบถ้วน
    • canonical resource IDs/order, models, parameters, capabilities และ dispatch
    • committed online/mode/reference configuration ปัจจุบัน
    • selector policy, SCR threshold และ gamma_req ที่ freeze ก่อนเห็นผล
    • สร้าง/ตรวจ selector_table_fingerprint เพื่อป้องกัน stale evidence

    ทำไม: candidate จาก topology หรือ dispatch เก่าห้ามนำมาใช้กับ runtime ใหม่ แม้ resource indices จะมีเลขเหมือนเดิม

  2. ตรวจ resource eligibility

    • resource online และอยู่ใน affected energized island
    • รองรับ GFL/GFM transition ตาม capability metadata
    • ไม่ติด hold, dwell หรือ lockout
    • มี device-owned transfer map สำหรับ transition ที่ต้องเกิด

    ทำไม: ลด search universe จาก IBR ทั้งหมดเหลือเฉพาะ resource ที่สั่งได้จริง โดยไม่ต้องเรียก PF

  3. แยก connected islands และบังคับ reference coverage

    • หา connected components จาก actual topology/Ybus
    • ทุก energized island ต้องมี supervisory reference owner หนึ่งตัว
    • หาก SG offline ต้องมี GFM-capable online resource อย่างน้อยหนึ่งตัวใน island นั้น
    • ห้ามใช้ heuristic “zone” แทน connected island จริง

    ทำไม: เป็นเงื่อนไขเชิงโครงสร้างที่จำเป็นและตรวจได้แบบ O(network size) จึงใช้ hard reject ได้อย่างปลอดภัย

  4. คำนวณ topology quantities ครั้งเดียว

    • SCR ของ online GFL candidates
    • electrical-distance matrix หรือ zonal descriptors สำหรับ ordering
    • linear sensitivities เช่น dV/dQ สำหรับ ordering หรือ conservative bound ที่พิสูจน์แล้วเท่านั้น

    ทำไม: ปริมาณเหล่านี้ขึ้นกับ topology/operating context มากกว่าตัว subset จึงควร cache ภายใต้ fingerprint ไม่คำนวณซ้ำทุก candidate

  5. บังคับ inclusion/exclusion ที่พิสูจน์ได้

    • IBR ที่ไม่มี GFM capability ถูก exclude จาก GFM subset
    • หาก contract กำหนดว่า online GFL ที่ SCR ไม่ผ่านต้องไม่คงเป็น GFL ให้ force เข้า GFM หรือ reject ถ้าทำไม่ได้
    • resource ที่ติด lockout หรือไม่มี transfer map ถูกห้าม transition

    ทำไม: constraint propagation ลดจำนวน binary choices ก่อนเริ่ม enumerate โดยยังรักษา exactness

  6. ใช้ conservative per-island headroom filter

    max_available_P(island) >= required_delta_P + loss_bound + P_margin

    • ตรวจทั้ง upward และ downward active-power capability ตาม dispatch/control contract
    • ตรวจ reactive reserve และ voltage-support capability
    • ตรวจ apparent-power/current circle เช่น P_i^2 + Q_i^2 <= S_i,max^2
    • นับเฉพาะ resource ที่ control contract อนุญาตให้รับ mismatch
    • margin/loss bound ต้องมี provenance และ freeze ก่อนผล ไม่ปรับเพื่อให้ candidate ผ่าน

    ทำไม: ถ้า upper bound ของ capability ยังไม่พอ candidate ย่อมไม่มีทางผ่าน nonlinear PF แต่การ “ผ่าน filter” ยังไม่ใช่หลักฐานว่า PF ผ่าน

  7. สร้าง candidate แบบ lazy ตาม lexicographic tier

    1. เริ่มจาก d = n_mode_changes = 0 แล้วเพิ่มทีละหนึ่ง
    2. ภายใน tier เดียวกันเรียง n_gfm_required ตาม frozen selector policy
    3. generate เฉพาะ candidate ของ tier ปัจจุบัน ไม่ materialize ทุก subset
    4. หากมี approved maximum simultaneous switches ให้ใช้เป็น operational transaction constraint ไม่ใช่แอบใช้แทน maximum GFM count

    ทำไม: ranking ปัจจุบันให้ความสำคัญกับจำนวน runtime mode changes จึงค้นหา tier ที่มีโอกาสชนะก่อน และหยุดก่อน tier ที่ด้อยกว่าได้เมื่อ proof condition ครบ

  8. จัดลำดับภายใน tier ด้วย heuristic

    • ให้ candidate ที่ครอบคลุม weak electrical areas ถูกประเมินก่อน
    • ใช้ electrical distance ลดการกระจุกตัว ถ้าต้องการ
    • ใช้ |dV/dQ|, SCR หรือ sensitivity score เป็น priority
    • ใช้ stable resource-ID tie-break เพื่อ deterministic repeat

    ทำไม: เพิ่มโอกาสพบ feasible candidate เร็ว แต่ห้าม hard reject เพราะ sensitivity และ zone เป็น local/heuristic evidence ไม่ใช่ nonlinear feasibility proof

  9. รัน mixed equilibrium / full-KCL gate

    • ใช้ project-owned warm start และ Newton path
    • ตรวจ convergence, KCL norm, dispatch consistency และ physical limits
    • candidate ที่ equilibrium ไม่ผ่านไม่ถูกส่งเข้า SSSA

    ทำไม: PF/equilibrium แพงกว่า algebraic filters แต่ถูกกว่า full SSSA และเป็น prerequisite ของ linearization ที่มีความหมาย

  10. รัน current/transfer instantaneous checks

    • device current และ apparent-power limits
    • transfer-state mapping และ continuity contract
    • right-limit consistency ที่จำเป็นก่อน commit

    ทำไม: steady equilibrium ที่แก้สมการได้อาจยังละเมิด hardware/controller capability

  11. รัน full-state SSSA เฉพาะ candidate ที่รอด

    • คำนวณ eigenvalues จาก mixed SG/IBR full-state model
    • ผ่านเมื่อ max(real(lambda)) <= -gamma_req
    • เก็บ margin, dominant mode และ complete candidate evidence

    ทำไม: SSSA เป็นด่านแพงสุด จึงควรถูกเรียกหลัง cheap proofs และ nonlinear equilibrium เท่านั้น

  12. เลือกผู้ชนะและพิสูจน์เงื่อนไขหยุด

    • ประเมิน candidate ทั้งหมดใน feasible lexicographic tier แรก
    • ภายใน tier เลือก stability margin ที่ดีกว่า แล้วใช้ resource-ID tie-break
    • หยุดก่อน tier ที่มี n_mode_changes แย่กว่า เพราะไม่สามารถชนะ ranking contract ได้
    • เก็บจำนวน generated/pruned/PF-called/SSSA-called เพื่อ audit performance

    ทำไม: การหยุดหลังพบ feasible ตัวแรกอาจพลาด candidate margin ดีกว่าใน tier เดียวกัน จึงต้องประเมินครบ tier ก่อน

  13. commit หรือ fail closed

    • ก่อน commit ตรวจ fingerprint, runtime modes, transfer maps และ right-limit KCL ซ้ำ
    • ถ้าไม่พบ feasible candidate: NO_FEASIBLE_CONFIGURATION
    • ถ้าหมด time/candidate budget ก่อน proof: SEARCH_INCOMPLETE
    • ห้ามนำ best-so-far มา commit โดยอัตโนมัติเมื่อ search incomplete

5. สถานะของ Pre-filter ที่เสนอ

แนวคิด บทบาทที่อนุมัติได้ เหตุผล เงื่อนไขก่อนใช้เป็น hard gate
Maximum k-switches TIER / POLICY ใช้ค้นหา Hamming-distance ต่ำก่อน ลด disturbance และตรงกับ runtime ranking ถ้าจะห้ามเกิน k จริง ต้องเป็น sourced/CASE_DEFINED operational constraint และต้องแยกจากจำนวน GFM
Algebraic headroom HARD-SAFE upper bound ที่ยังต่ำกว่าความต้องการพิสูจน์ infeasibility ได้โดยไม่รัน PF ต้อง conservative, per-island, control-aware และรวม P/Q/S/current/loss bounds
Electrical distance / zones ORDER ONLY ช่วยประเมินชุดที่กระจายตัวก่อน แต่ zone boundary ไม่ใช่ physical island ใช้ hard gate ได้เฉพาะ constraint ที่พิสูจน์เป็น necessary condition; connected-island coverage เป็นคนละกรณีและ hard-safe
dV/dQ sensitivity ORDER ONLY บอก local voltage weakness ณ operating point แต่เปลี่ยนตาม controls, limits และ PV/PQ behavior ต้องมี conservative bound ที่พิสูจน์เทียบ nonlinear PF ก่อนจึง hard prune ได้
SCR capability gate HARD-SAFE ตาม frozen contract เป็น acceptance gate ที่มี threshold/provenance อยู่แล้ว ต้องใช้ topology/resource rating ที่ fingerprint รับรอง และไม่ปรับ threshold เพื่อเร่ง search

6. ภาพรวมการไหลของข้อมูล

Case + topology + canonical resources + committed runtime configuration
        |
        v
Authenticate fingerprint and resource identities
        |
        v
Eligibility + exact island coverage + forced capability constraints
        |
        v
Conservative per-island P/Q/S/current headroom pruning
        |
        v
Lazy tiers: runtime mode changes -> GFM count
        |
        v
Order only: electrical distance + dV/dQ + stable resource-ID
        |
        v
Mixed equilibrium / full KCL -> current/transfer checks -> full SSSA
        |
        v
Complete first feasible tier -> margin -> resource-ID tie-break
        |
        +---- proof complete ----> authenticated commit
        |
        +---- budget exhausted -> SEARCH_INCOMPLETE, no commit

7. Pseudocode ระดับสถาปัตยกรรม

context = authenticate(case_data, resources, topology, committed_state)
eligible = resolve_mode_eligible_resources(context)
constraints = derive_exact_island_and_capability_constraints(context)

for d = 0:N                      % runtime mode-change tier
    tier = lazy_generate(eligible, constraints, d)
    tier = hard_prune_headroom_bounds(tier, context)
    tier = order_only(tier, electrical_distance, dVdQ, resource_ids)

    feasible = []
    while tier.has_next()
        assert_search_budget_or_fail_closed()
        candidate = tier.next()

        eq = mixed_equilibrium_full_kcl(candidate)
        if ~eq.pass, record_reject(candidate, eq); continue; end

        limits = current_and_transfer_checks(candidate, eq)
        if ~limits.pass, record_reject(candidate, limits); continue; end

        sssa = full_state_sssa(candidate, eq, gamma_req)
        if ~sssa.pass, record_reject(candidate, sssa); continue; end

        feasible.append(candidate, eq, limits, sssa)
    end

    if ~isempty(feasible)
        winner = rank_margin_then_resource_id(feasible)
        return authenticated_commit_candidate(winner)
    end
end

return NO_FEASIBLE_CONFIGURATION
Pseudocode นี้ตั้งใจไม่ระบุว่า d หรือ n_gfm_required ต้องมีค่าสูงสุดเท่าใด เพราะ maximum ต้องมาจาก approved operational contract ไม่ใช่ค่าที่ตั้งเพื่อให้โปรแกรมเร็วขึ้น

8. แผนพิสูจน์ว่า Lazy Search ยัง Exact

  1. IEEE14 exhaustive oracle
    • เก็บการ enumerate 16 subsets ทั้งหมดเป็น oracle
    • เปรียบเทียบ selected resource IDs/indices, reference ownership, feasibility, margin และ rejection reasons
    • Lazy selector ต้องให้ผู้ชนะเดียวกัน ไม่ใช่เพียง “ได้ candidate ที่ผ่าน”
  2. Synthetic small-N equivalence
    • สร้างกรณี N ประมาณ 6–10 ที่ exhaustive ยังรันได้
    • เปรียบเทียบ hard-pruned/lazy กับ exhaustive ทุก seed/configuration ที่ predeclared
    • พิสูจน์ว่า hard filter ไม่เคยตัด exhaustive optimum
  3. Index-contract tests
    • สลับ resource table ordering แล้ว fingerprint ต้องเปลี่ยน
    • stable device-ID mapping ต้องให้ physical configuration เดิมเมื่อ remap อย่างถูกต้อง
    • bus number และ state index ที่ถูกส่งมาแทน resource index ต้อง fail closed
  4. Hard-vs-order tests
    • เปลี่ยน electrical-distance / sensitivity score แล้ว evaluation order เปลี่ยนได้ แต่ final winner ห้ามเปลี่ยน
    • สร้าง candidate ที่ heuristic ให้คะแนนต่ำแต่ feasible เพื่อยืนยันว่าไม่ถูกตัด
    • ทดสอบ distinction ระหว่าง n_gfm_required กับ n_mode_changes
  5. Budget and fail-closed tests
    • candidate budget หมดก่อนจบ tier ต้องคืน SEARCH_INCOMPLETE
    • ห้ามมี committed configuration หรือ right-limit sample จาก best-so-far
    • rejected trial ต้องไม่เดิน hold/dwell/lockout timers
  6. Performance evidence
    • บันทึก candidates generated, hard-pruned, equilibrium calls, SSSA calls และ wall time แยกกัน
    • รายงาน worst case อย่างซื่อสัตย์: exact search ยังมี exponential worst case
    • ห้ามเพิ่ม dt หรือลด numerical tolerance เพื่อทำให้ selector ดูเร็วขึ้น

9. สิ่งที่ต้อง Freeze ก่อนเขียน Production Code

  • ranking contract ที่แน่นอน: mode changes, GFM count, stability margin และ resource-ID tie-break
  • นิยาม headroom ต่อ island รวม dispatch participation, losses, P/Q/current และ provenance ของ margin

10. ข้อสรุป

  • IEEE14 ที่มี 4 IBR ควรคง exhaustive 16-subset route ไว้เป็น oracle
  • ระบบขนาดใหญ่ใช้ exact lazy enumeration + constraint propagation แทนการ materialize 2^N
  • Headroom และ connected-island coverage ใช้ hard pruning ได้เมื่อ formulation conservative และมี provenance
  • Electrical distance และ dV/dQ ใช้จัดลำดับก่อน จนกว่าจะพิสูจน์ conservative rejection bound ได้
  • Index ทุกตัวต้อง resolve ผ่าน canonical resource table และ stable device ID; ห้ามใช้ตัวเลขคงที่โดยไม่มี schema/fingerprint validation
  • ถ้ายังพิสูจน์ search completion ไม่ได้ ต้อง fail closed ด้วย SEARCH_INCOMPLETE
  • วิธีนี้ลดจำนวน PF/SSSA calls ได้มากในกรณีทั่วไป แต่ไม่ปิดบังว่า exact search ยังมี exponential worst case
