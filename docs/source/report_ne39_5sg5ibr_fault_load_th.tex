\begin{abstract}
รายงานนี้บันทึกการศึกษาลำดับเหตุการณ์ทรัพยากรผสมของระบบ NE39 (New England IEEE 39 บัส)
ของโครงการ เครือข่าย 39 บัสประกอบด้วยเครื่องกำเนิดซิงโครนัสห้าเครื่องที่บัส 31, 32, 35, 38, 39
(แต่ละเครื่องเป็นแผนงานคลาสสิกสอง state $\vect x=[\delta,\omega]$) และตัวแปลงสองโหมด Dual-mode-IBR
ห้าตัวที่บัส 30, 33, 34, 36, 37 (GFM สองตัว, GFL สามตัวตามกฎการออกแบบ deterministic)
เพราะเครื่องปั่นห้าตัวออนไลน์ตลอดการรัน กองเครื่องปั่นยังคงเป็น reference แรงดัน/ความถี่ของระบบ
ทุกช่วงเวลา --- ครอโนโลยีจึงไม่มีเหตุการณ์เบรกเกอร์ SG ใดๆ เลย: ไม่มีการทริป SG, ไม่มีการปิดซ้ำ SG,
และไม่มีคำถามเรื่อง hand-back การรบกวนคือฟอลต์ที่บัส~16 (thแข็ง $Z_f=j0.1$~pu,
60--60.15~s) ตามด้วยสเต็ปโหลดรวม $+20\%$ ที่ 100~s, เพดาน 160~s, โดยจุดเวลาเหตุการณ์ตรงกับ
การศึกษา 160~s ที่ส่งมอบแล้วเพื่อให้หน้าต่างฟอลต์เทียบได้ตรง กราฟตัวเลขเรนเดอร์โดย MATLAB จากไฟล์ CSV
ที่ส่งออกจากชุดผลที่เก็บไว้ การทดลองเปลี่ยนโหมดไปข้างหน้าที่จุดทริป \emph{ยังไม่ได้รับการรับรองเพราะงบหลักฐาน}
(งบ step ที่แบ่งกันของ mesh ส่วนต้องมี เกณฑ์ทางกายภาพทุกตัวยังเขียว ถึง state ยืนยันสุดท้าย)
การรันนี้เสร็จสมบูรณ์เฉพาะภายใต้ การประกาศ study continuation อย่างชัดเจน เกณฑ์ที่ไม่ผ่าน
การปฏิเสธ และใบรับรองที่ยังค้าง ถูกรายงานไว้ ไม่ได้ถูกปรับให้หายไป
\end{abstract}

\section{ขอบเขต แหล่งอ้างอิง และการทำซ้ำได้}\label{sec:scope}

ระบบที่ศึกษาคือเครือข่าย TAMU New England 39 บัส ที่มี SG แบบจำลองห้าเครื่อง
(บัส 31/32/35/38/39) และ IBR แบบจำลองห้าตัว (บัส 30/33/34/36/37) ระบบทั้งหมด
ประกอบเป็นระบบ differential--algebraic แบบประกอบ all-KCL ชุดเดียว โดย SG และ IBR
ทุกตัวส่งบล็อก state เชิงอนุพันธ์ของตัวเองและการฉีดของตัวเอง ไม่มีอุปกรณ์ใดถูกมอบให้
ตัวแก้ โมเดล หรือโปรแกรมอ้างอิงภายนอก

\paragraph{ทำไมจึงไม่ทริป SG.}
เมื่อเครื่องปั่นซิงโครนัสห้าเครื่องเชื่อมต่ออยู่ การเปิดเบรกเกอร์ใดเบรกเกอร์หนึ่งยังเหลือ
เครื่องปั่นสี่เครื่องคอยรักษา reference แรงดัน/ความถี่ของเครือข่าย --- คำถามเชิงกายภาพที่
การศึกษา 160~s ที่ส่งมอบแล้วตอบไปแล้ว (``ตัวแปลงจะรักษาเกาะหลังเครื่องปั่นออกได้หรือไม่'')
จึงไม่เกิดขึ้น ครอโนโลยีนี้จึงถามคำถามต่างออกไป: \emph{กองทรัพยากรผสมขี่ฟอลต์ผ่านและ
ดูดซับสเต็ปโหลดได้หรือไม่ โดยที่ reference ของเครื่องปั่นยังคงอยู่} ตามนั้น โปรไฟล์
\code{fault_load_step} ที่มี fault + load step (และไม่มีเหตุการณ์เบรกเกอร์ SG) ถูกเพิ่ม
เข้าไปใน event schedule และแถว catalog \code{fault_load_step20} ตรึงจุดเวลาของมันก่อน
ที่ผลลัพธ์ใดจะถูกอ่าน

\paragraph{แหล่งกราฟและสัญญาไม่มีสัญญาณสังเคราะห์.}
กราฟภาคเวลา (ส่วน~\ref{sec:transient}) เรนเดอร์จาก trajectory ที่ยอมรับของชุดผล
ที่เก็บไว้ โหลดเพียงครั้งเดียวและส่งออกเป็นหลักฐาน CSV เพื่อการนำเสนอ
ทุกตัวอย่างที่พล็อตเป็นค่าที่ยอมรับดิบ ไม่มีอะไรถูก smooth, filter, decimate,
clip, offset, interpolate หรือเติมสัญญาณรบกวนสังเคราะห์ ตัวเลขทุกตัวในรายงานนี้
คัดลอกจากรันที่เก็บไว้หรือคำนวณจากสมดุลที่มันเก็บไว้ ไม่มีเกณฑ์ใดถูกผ่อนและ
ไม่มีการจำลองซ้ำ

\paragraph{Classification.}
สมการ SG AC/flux และสมการ IBR AC/control ถูกระบุเป็น
\textsf{SOURCE\_MAPPED} หรือ \textsf{PROJECT\_DERIVED} ตามฉลากที่ปรากฏครั้งแรก
พารามิเตอร์เครื่องและตัวแปลง, per-unit bases, และเวลาการรบกวนเป็น
\textsf{CASE\_DEFINED}; ตัวทำนายและนโยบายแบ่งขั้น step เป็น
\textsf{NUMERICAL\_METHOD} การจำแนกประเภทของรันและ flag
\code{production_certified=false} ถูกนำมาจาก manifest ไม่ได้ตัดสินใจซ้ำที่นี่
